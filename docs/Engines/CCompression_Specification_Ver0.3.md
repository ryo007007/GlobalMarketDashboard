# CCompression Specification Ver.0.3

## 1. 目的

CCompression は、市場の変動幅の縮小を中心として、市場がCompression状態にある可能性を検出し、その後の状態変化を観測する。ADXはトレンド強度を評価する補助指標として使用する。

### 重要
CCompression は以下を**行わない**：
- 上昇予測
- 下落予測
- ブレイクアウト予測
- 方向判定
- 波及先の予測
- 先行・追随の確定

あくまで以下の市場状態を検出する：
```
NORMAL → COMPRESSION → STRONG COMPRESSION → TIGHT COMPRESSION → TRANSITION
```

| Percentile | 過去 125 期間の ATR% 分布における現在値のパーセンタイル |

| 項目 | 設定 |
|------|------|
| Period | 20 |
| Deviation | 2.0 |

### Score
| Percentile | Score |
|------------|-------|
| 0 ～ 20    | 2     |
| >20 ～ 40  | 1     |
| >40        | 0     |

## 6. ADX

| 項目 | 設定 |
|------|------|
| Period | ADX(14) |
| 判定方式 | Percentile ではなく**絶対値**を使用 |

ADXについてはATR等と違って、Percentileではなく絶対値から開始する。  
ADXはCompressionの必須条件ではなく、トレンド強度を評価する補助スコアとして使用する。

### Score
| ADX値     | Score |
|-----------|-------|
| < 15      | 2     |
| 15 ～ <20 | 1     |
| ≥ 20      | 0     |

## 8. 状態遷移（Delta による観測）

Ver.0.3 では、正式な `BUILDING` / `RELEASE` 状態は持たない。

現在取得可能な情報は以下：
- Score
- Previous Score
- Delta
- Age
- State

**Delta から Compression の強弱変化を観測する。**

例：
- Score 3 → 4（Delta +1） → Compression Strengthening
- Score 5 → 4（Delta -1） → Compression Weakening

将来 Dashboard で `BUILDING` / `RELEASING` 表示を追加するのは別の改良として扱う。

---

## 9. TRANSITION

**TRANSITION は、単なる Score 低下では発生させない。**

以下の **3 条件をすべて満たした場合** に TRANSITION とする。

### 条件A
前回状態が以下のいずれか：
- STRONG COMPRESSION
- TIGHT COMPRESSION

### 条件B
```
Current Score < Previous Score
```

### 条件C
現在の値が前回値より上昇している：
```
ATR% > 前回ATR%
または
BB Width > 前回BB Width
```

3 条件を満たすと `TRANSITION` となる。

---

## 10. 方向判定を行わない

CCompression は「圧縮が解除され始めた」ことまでを検出する。

その後の方向は以下の別 Engine から取得する：

```
CCompression
      ↓
TRANSITION
      │
      ├── Currency Strength
      ├── Strength Gap
      ├── Money Flow
      └── Market Regime
```

CCompression 自身が方向性を出力しない設計を維持する。

### 追加原則（Ver.0.3）
- CCompression は「波及先予測」も「先行・追随の確定」も行わない。
- 市場間の関係は「観測済み」「仮説」「未確認」に分類し、推測を確定シグナルのように見せない。
- 「先行して動いた」という事実と、「予測に役立つ」という事実は別物として扱う。
- サイン数が多いことは、その通貨が今後大きく動くことや、利益を得やすいことを**保証しない**。

## 12. Delta

```
Delta = Current Score - Previous Score
```

例：
- 2 → 3 = +1
- 3 → 5 = +2
- 4 → 3 = -1

Compression の強さが強まっているか弱まっているかを示す指標。

---

## 13. Age

```
Age = 現在の STATE 何回連続して続いているか
```

実装ルール：
- 前回 State == 今回 State → Age + 1
- State が変化 → Age = 1

例（H4 の場合）：
```
H4 #1  NORMAL
H4 #2  COMPRESSION  → Age 1
H4 #3  COMPRESSION  → Age 2
H4 #4  COMPRESSION  → Age 3
H4 #5  COMPRESSION  → Age 4
H4 #6  NORMAL       → Age 1（リセット）
```

## 17. 市場活動度一覧（第2段階仕様）

### 17.1 目的

「価格が上がった市場」を活発とするのではなく、普段と比べて値動きや状態変化がどれほど大きくなっているかで判断する。最初は方向予測を付けない。

### 17.2 観測項目

| 観測項目 | 見たいもの |
|---------|-----------|
| 値動きの大きさ | ATR比などで、普段より大きく動いているか |
| 急変の強さ | ROC Zなどで、変化が急激か |
| 圧縮からの変化 | COMPRESSIONからTRANSITIONへ移ったか |
| 継続性 | 一瞬のヒゲだけか、複数本にわたり動いているか |
| 市場間の広がり | 1銘柄だけか、関連市場にも変化が広がっているか |

### 17.3 通貨強弱の観点

たとえば EUR/USD、EUR/JPY、EUR/CAD がほぼ同じ時間に下落した場合、3つの独立した出来事として数えるだけでは不十分である。EUR が共通しているため、EUR を含む通貨ペアに共通した動きが起きている可能性を考える。

ただし、EUR の弱さが原因なのか、USD や JPY 側の動きなのかは、各通貨の強弱や他のペアも見て判断する。

### 17.4 出力イメージ（案）

```
## Market Activity Monitor（観測用）

| Market | Symbol | Activity Level | ATR Ratio | State Change | Notes |
|--------|--------|---------------|-----------|--------------|-------|
| FX | EUR/USD | High | 1.8x | TRANSITION | EUR weakness suspected |
| FX | EUR/JPY | High | 2.1x | TRANSITION | Same cluster as EUR/USD |
| FX | USD/JPY | Normal | 1.0x | COMPRESSION | - |
| Crypto | BTC/USD | Elevated | 1.5x | NORMAL | ATR rising |
```

> **注記：上記の「Notes」欄の記述は仮説であり、確定ではない。「suspected」などの現を用い、推測を確定として見せない。**

## 18. 金利監視項目（将来拡張）

単に米国10年債利回りを表するだけでなく、将来的には金利を以下の視点に分けて監視する。

| 指標候補 | 何を見たいか |
|---------|------------|
| 米国2年債利回り | 政策金利見通しの変化に比較的敏感 |
| 米国10年債利回り | 長期金利の上昇・低下 |
| 米国10年実質金利 | インフレ期待を考慮した金利環境 |
| 2年・10年の利回り差 | 短期と長期の金利見通しの変化 |

### 18.1 観測上の注意

- 高金利そのものだけでなく、金利が**急速に上昇していること**にも注意する。
- 金利上昇と Nasdaq 下落が同時に起きた場合、株式の評価に影響する金利上昇が関係している可能性がある。
- 一方、景気気悪化への懸念から金利が低下して株式も下落することもある。
- **したがって、金利の水準だけでリスクオン・オフを決めない設計とする。**

## 19. CCompression Market Watch（第2段階仕様）

### 19.1 目的

各チャートに圧縮やTRANSITIONのサインが出る現状から、たくさんのチャートを見回さなくても「今日はどの通貨に注目すべきか」が分かる一覧画面を提供する。これは将来の「本日の通貨注目度」機能の基礎となる。

### 19.2 基本設計

本日のサイン数・圧縮・遷移・急変を通貨別に集計する。

#### 表示例（イメージ）

```
## CCompression Market Watch

| 通貨 | サイン数 | 状態 | 注目度 |
|------|---------|------|--------|
| CHF | 集計待ち | 要確認 | — |
| EUR | 集計待ち | 要確認 | — |
| GBP | 集計待ち | 要確認 | — |
| USD | 集計待ち | 要確認 | — |
| AUD / NZD | 集計待ち | 要確認 | — |
| JPY / CAD | 集計待ち | 要確認 | — |
```

> **注記：上記は表示例であり、現在のログを自動集計した実データではない。**

### 19.3 集計項目の定義

単純なサイン数ランキングではなく、以下の4項目を分けて表示する。

| 項目 | 定義 | 集計対象 |
|------|------|---------|
| **活動度** | 今日、その通貨に関係するサインが何回出たか | 該当通貨を含む全ペアのState変化回数 |
| **圧縮度** | 圧縮状態にあるペアがどれだけあるか | 該当通貨を含むペアのうち、COMPRESSION以上のStateの数 |
| **変化度** | COMPRESSIONからTRANSITION、あるいは急変へ移ったペアがあるか | 該当通貨を含むペアのTRANSITION発生回数、およびATR急増検知回数 |
| **方向の偏り** | その通貨が相手通貨に対して強いのか弱いのか | 該当通貨を含むペアの値動き方向の集計（※仮説層） |

#### 方向の偏りの算出方法（案）

通貨を含む各ペアについて、確定バーの終値と始値を比較する。

- 通貨が**ベース通貨**の場合：`Close > Open` → 強い方向に寄与
- 通貨が**相手通貨**の場合：`Close < Open` → 強い方向に寄与

例：EUR について
- EUR/USD: Close > Open → EUR 強寄与 +1
- EUR/JPY: Close < Open → EUR 弱寄与 -1
- EUR/GBP: Close > Open → EUR 強寄与 +1

偏りコア = 強寄与数 − 弱寄与数

> **重要：方向の偏りは仮説層に属する。CCompression は方向判定を行わない設計を維持するため、方向の偏りは「注目候補の補助情報」として位置づけ、確定シグナルとして扱わない。**

### 19.4 通貨クラスタリング

単一通貨ではなく、関連通貨をグループ化して表示することも検討する。

| グループ | 通貨 | 理由 |
|---------|------|------|
| 欧州 | EUR, GBP, CHF | 州セッション・地政学リスクの共通性 |
| 商品 | AUD, NZD, CAD | 商品価格・資源価格への感受性 |
| 安全資産 | JPY, CHF, USD | リスク回避時の資金流入先 |
| 米州 | USD, CAD | 北米経済・金利政策の連動 |

> **注記：グループ表示は観測の補助であり、グループ内通貨が必ずしも同方向に動くことを保証するものではない。**

### 19.5 出力イメージ（詳細版・案）

```
## CCompression Market Watch（詳細版・案）

| 通貨 | 活動度 | 圧縮度 | 変化度 | 方向偏り | 注目度 | 備考 |
|------|--------|--------|--------|----------|--------|------|
| EUR | 5 | 3 | 2 | 弱寄与(-2) | 高 | 3ペアでTRANSITION観測 |
| CHF | 4 | 2 | 1 | 強寄与(+1) | 中 | 安全資産フロー疑い（仮説） |
| USD | 3 | 2 | 0 | 中立(0) | 低 | 方向がそろっていない |
| JPY | 2 | 1 | 0 | 弱寄与(-1) | 低 | - |

※ 注目度は活動度・変化度を中心に機械的に算出する仮評価であり、
  売買推奨や方向予測ではない。
```

## 20. 「今日のねらい」の判断条件（将来拡張）

サインが多い通貨をそのまま売買候補の1位にするのは危険である。将来的に「注目候補」を絞り込む際は、以下の条件を組み合わせて検討する。

### 20.1 検討条件

| 条件 | 内容 | 観測方法 |
|------|------|---------|
| 1. 複数ペアでの変化 | 複数の通貨ペアで変化が見られる | Market Watch の活動度・変化度で確認 |
| 2. 圧縮後のTRANSITION | 圧縮後にTRANSITIONが発生している | State遷移ログで確認 |
| 3. ブレイク方向の確認 | ブレイク方向が確認できる | CCompression では判定しない。別Engineまたは目視確認 |
| 4. だまし・レンジ戻りの少なさ | だましやレンジへの戻りが少ない、または過去データで検証されている | 過去のTRANSITION後の値動きを統計的に評価 |

### 20.2 重要な制約

- サイン数が多いことは、その通貨が今後大きく動くことや、利益を得やすいことを**保証しない**。
- 最初は「**注目候補**」として表示し、十分な検証後に予測評価へ進める。
- 「今日のねらい目」は、CCompression Market Watch の上に構築する別層の機能とする。
- CCompression 自身は、ねらい目の選定や方向予測を行わない。

## 21. 開発ロードマップ（段階的実装計画）

CCompression の軸を保ちながら、Global Market Dashboard へ段階的に発展させる順序。

### 第1段階：CCompression の検証を継続（現在）
- 圧縮検出、TRANSITION、急変検知の時刻と、その後の値動きを記録する。
- 現状の検出条件は維持する。
- 対象：個別チャート（主要FXペア、GOLD等）。

### 第2段階：市場活動度の一覧を作る
- FX、暗号資産、商品、株式指数、VIX、債券について、値動きの強さと状態変化を一覧化する。
- **CCompression Market Watch（通貨別サイン集計）を実装する。**
- 最初は方向予測を付けない。
- 出力は「観測済み」のみとし、仮説は明確に区別する。

### 第3段階：先行・追随の記録を追加する
- 市場間の変化時刻を比較し、5分・15分・30分どの時間差を調べる。
- セッションや経済指標発表の影響も区別する。
- 「先行した」とは記録するが、「予測に役立つ」かどうかは別途検証する。

### 第4段階：波及仮説を表示する
- 再現性が確認できた関係だけを使い、「追随の可能性」などとして表示する。
- 表示を「観測済み」「仮説」「未確認」に分け、推測を確定シグナルのように見せない。

### 第5段階：方向・時間の予測を証する
- 「15分後に上昇」「30分後に下落」といった予測は、過去データで精度を評価してから追加する。
- 精度が検証されるまでは、予測機能を本番表示に組み込まない。

### 第6段階：「今日のねらい目」の選定機能（将来）
- 第2〜5段階の検証結果を基に、注目候補の絞り込み機能を検討する。
- 売買推奨ではなく、「注目度の高い通貨・ペアの提示」に留める。

### 当面の推奨
- 第1段階を続けながら、第2段階の仕様（市場活動度一覧・CCompression Market Watch）だけを整理する。
- 新しい市場分析機能をいきなり実装する必要はない。

## 22. 設計原則と制約

### 22.1 観測と仮説の分離
- 観測された事実（State, Delta, TRANSITION, ATR変化など）と、仮説（波及先、先行・追随、通貨強弱の原因、方向の偏りなど）を明確に分離する。
- 仮説は「観測済み」「仮説」「未確認」に分類して表示する。

### 22.2 確定シグナルとして見せない
- 「追随の可能性」「EUR弱さの疑い」など、不確実性を含む表現を用いる。
- 数値や方向を予測する場合は、信頼区間や過去の再現性を併記する。

### 22.3 「先行した」≠「予測に役立つ」
- 最初に動いた市場を特定することだけが目的はない。
- その先行変化が、他の市場の値動きを予測するのに役立つかどうかを、過去データで検証する必要がある。
- この違いを守ることで、CCompression から脱線せず、将来の Global Market Dashboard につながる形で整理する。

### 22.4 CCompression の軸の維持
- CCompression はあくまで「圧縮とその解除の検出」に特化する。
- 市場間分析、方向予測、波及予測、通貨注目度の選定は、CCompression の上に構築する別層の機能と置づける。

### 22.5 サイン数≠利益保証
- サイン数が多い通貨をそのまま売買候補にするのは避ける。
- 「注目候補」「観測対象」として位置づけ、予測評価は十分な検証後に行う。
